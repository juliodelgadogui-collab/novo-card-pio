CARDAPIO - V9.7 - CORRECAO COZINHA / KDS
===========================================
ATENCAO: apenas para a instalacao /home/gestorstore/go.gestao2.store/1/

CAUSA IDENTIFICADA NO CODIGO
Em ProductionService::board(), versionHash($rows) era chamada inclusive quando
$rows estava vazio. versionHash([]) invocava board() novamente, provocando
recursao infinita se a fila do KDS nao tinha itens. Isso pode travar o PHP,
consumir recursos e produzir erro 503 ou ERR_CONNECTION_ABORTED.

ALTERACOES
1. src/Services/ProductionService.php
   - versionHash usa parametro ?array = null e diferencia [] de null.
   - A fila vazia agora gera hash estavel e nao provoca novas consultas.
   - expedition(bool $refreshPendingJobs = true): opcao para nao repetir a
     sincronizacao pesada depois de board(), mantendo comportamento original
     por padrao para API, desktop e outros chamadores.
2. app/routes/kitchen.php
   - Mantem a captura de erros V9.6.
   - Chama expedition(false) pois board() ja sincronizou os pedidos.

INSTALACAO VIA CPANEL
1. Faca copia dos DOIS arquivos atuais.
2. Extraia o ZIP em /home/gestorstore/go.gestao2.store/1/ mantendo a estrutura
   das pastas. Confirme a substituicao APENAS destes 2 arquivos.
3. Verifique a sintaxe pelo Terminal:
   cd "$HOME/go.gestao2.store/1" && php -l src/Services/ProductionService.php && php -l app/routes/kitchen.php
4. Teste https://go.gestao2.store/1/?route=kitchen (logado no sistema).
5. Se ainda mostrar 503, consulte os logs e envie a referencia do erro.

NENHUMA migracao SQL, alteracao de credenciais ou alteracao de dados.
COMPATIVEL com a V9.6 em uso. NAO substitua o sistema completo.

VALIDACAO LOCAL
Sintaxe PHP dos dois arquivos; teste de regressao do hash vazio.
Nao foi possivel executar teste de producao hospedado neste ambiente.
